# TK-TH 可行性与利润最大化执行手册

## 1. 投资结论

本项目当前适合被定义为“低成本验证系统”，不适合被定义为“自动赚钱系统”。
可行性是**有条件成立**：先用真实、可追溯的数据找需求，再用小批量/样品和达人纯佣验证转化，
只有在贡献利润、退款/拒收和现金周转同时过线后才扩大库存与广告。

原版本的主要问题不是代码能否运行，而是决策口径错误：真实数据失败后会生成随机商品继续推送，
“利润分”也只看售价。两者叠加会造成高分假象。优化后的系统采用真实数据失败即停，
并用单均贡献利润、最大 CPA 和盈亏平衡 ROAS 作为硬闸门。

## 2. 多维可行性

| 维度 | 判断 | 关键条件 |
|---|---|---|
| 市场 | 可测试 | 只聚焦泰国和 1 个细分类目，避免同时铺 TH/VN/MY 稀释预算 |
| 产品 | 有条件可行 | 非强监管、非易碎、非高尺码退货、视频 3 秒内能展示价值 |
| 内容 | 可行 | 泰语本地化、达人原生素材、每周持续迭代钩子而非一次性拍大片 |
| 达人 | 可行 | 先 KOC 纯佣/样品，按成交和退款后利润续约，不按粉丝数买量 |
| 财务 | 取决于数据 | 贡献利润率至少 12%，保本 ROAS 不高于 3.5，库存周转不超过 30-45 天 |
| 运营 | 有条件可行 | 本地履约、售后 SLA、库存准确率和退货原因闭环必须建立 |
| 合规 | 必须前置 | 店铺主体、税务、类目资质、商品宣称、音乐/素材授权均需人工核验 |
| 技术 | 可行 | CSV + SQLite + GitHub Actions/本地任务足以完成验证；规模化后再买 API |

## 3. 单位经济模型

系统按“每一个下单”估算：

```text
实际收入 = 售价 x (1 - 卖家优惠率) x COD接单率 x (1 - 退货率)
贡献利润 = 实际收入 - 商品损失 - 平台/支付/达人费 - 正逆向物流 - 广告
最大CPA = 广告前贡献利润
保本ROAS = 实际收入 / 最大CPA
```

`config.sea.yaml` 中的费率仅为保守起点，必须替换成你自己的合同与实绩。
以售价 20 USD 和当前默认假设举例：预计实际收入 16.59 USD、广告后贡献利润 2.80 USD、
贡献利润率约 16.9%、最大 CPA 5.20 USD、保本 ROAS 约 3.19。若退货、COD 拒收和广告占比同时恶化，
贡献利润率会迅速接近 0；所以 GMV、订单量和 ROAS 都不能单独代表赚钱。

## 4. 利润最大化策略

### 选品

优先选择“高可视化价值 + 低售后复杂度 + 可组合加购”的商品。首轮排除食品/保健品、医疗功效宣称、
高尺码依赖服装、易碎大件、液体跨境高风险品。不要从泛品类开始；用一个明确人群、一个场景、
一个价格带建立内容密度。

候选品进入样品阶段前必须同时满足：真实销量趋势为正、评论痛点可被产品解决、供应商可稳定补货、
压力情景下不亏损。压力情景至少把广告率、退货率和 COD 拒收率分别上调 50%。

### 达人与内容

首轮采用 20-30 个小达人/KOC 的样品或纯佣测试，不预付高额坑位费。评价达人时使用：
千次有效观看成交数、退款后 GMV、每条素材贡献利润、素材可复用率。粉丝量只作辅助字段。

每个商品至少测试 3 类钩子：痛点演示、前后对比、价格/组合价值；每类 3-5 个变体。
保留原始素材授权和 Spark Ads/广告使用权限，胜出素材再加预算。

### 广告

先让自然流量和达人验证 CVR，再用广告放大。出价上限应由最大 CPA 推导，而不是写死 CPC。
24 小时止损同时看有效点击、加购、成交和退款后贡献利润；数据量不足时延长观察，不因单个订单误判。

### 供应链与现金流

首批库存只覆盖 14-21 天的保守销量；将补货周期、平台结算周期、退款冻结和税费纳入现金缺口。
任何时候都保留至少 2 个补货周期的现金缓冲。扩大库存前要求连续两周贡献利润为正，且退款/拒收稳定。

## 5. 分阶段资金闸门

| 阶段 | 建议投入 | 通过条件 | 失败动作 |
|---|---:|---|---|
| 数据验证 | 0-50 USD | 20 个真实候选品，字段完整且来源可追溯 | 补数据，不运行模拟投资建议 |
| 样品验证 | 100-300 USD | 3-5 个样品通过质量、内容和合规检查 | 淘汰问题品，不补库存 |
| 达人测试 | 300-800 USD | 至少 3 条素材产生真实成交，退款后贡献利润为正 | 换钩子/达人，限制继续送样 |
| 小额投放 | 每品 20-50 USD/日 | 7 天贡献利润率 >=12%，实际 ROAS 高于保本线 20% | 自动/人工暂停并复盘 |
| 放量 | 逐周 +20%-30% | 14 天利润稳定、库存和履约无恶化 | 回退上一预算档 |

金额是风险预算框架，不是收益承诺；应按你的可承受损失调整。

## 6. 免费工具组合

| 任务 | 免费优先工具 | 用法 |
|---|---|---|
| 趋势/创意 | TikTok Creative Center | 人工记录泰国热门商品、关键词、素材结构 |
| 店铺实绩 | TikTok Seller Center Analytics | 导出订单、退款、流量和商品表现 |
| 搜索需求 | Google Trends | 对比泰语关键词的方向，不把指数当销量 |
| 数据清洗 | Google Sheets / LibreOffice | 按 `data/input/products.example.csv` 统一字段 |
| 运行与存储 | Python + SQLite | 本地零成本执行与留痕 |
| 调度 | Windows Task Scheduler / GitHub Actions | 有真实新数据时运行；静态 CSV 不应重复分析 |
| 看板 | 当前 Streamlit 页面 | 观察候选趋势；财务决策以贡献利润表为准 |

付费数据 API 只在“手工收集时间成本 > API 月费且模型已盈利”后购买。EchoTik 如接入必须使用官方
Basic Authentication（`ECHOTIK_USERNAME` / `ECHOTIK_PASSWORD`），不再使用浏览器 Cookie 或猜测网页接口。

## 7. 你需要手动完成

1. 在 TikTok Creative Center 与 Seller Center 获取泰国真实数据，复制
   `data/input/products.example.csv` 为 `data/input/products.csv` 并替换示例行。
2. 把 `config.sea.yaml -> unit_economics.markets.th` 全部替换为你的真实成本、平台类目费率、
   达人佣金、广告占比、退款/COD、物流和包装成本。
3. 核验店铺主体、泰国税务、商品资质、标签/语言、功效宣称、音乐和达人素材授权；代码不能替代法律意见。
4. 首次运行 `python scheduler.py --region sea --once --markets th`；只有演示界面时才加 `--demo`。
5. 有真实评论和明确收益后再开启 AI 情感分析；验证阶段可人工编码前 50 条评论以保持零成本。
6. 若选择 EchoTik API，先从其 API Dashboard 获取专用账号密码并只存环境变量，切勿提交到 Git。

## 8. 核心 KPI

一级指标只有一个：**退款/拒收后贡献利润**。二级指标包括贡献利润率、最大 CPA、实际 ROAS 与保本 ROAS
安全垫、库存周转天数、退款率、COD 拒收率、达人素材盈利率。GMV、播放量、点赞和粉丝增长属于诊断指标，
不得替代利润指标。
